# 第一部分　先建认知地图

## 1.1 一句话：这个项目在做什么

**给一个来申请贷款的人打分，决定批不批。**

打分的依据只能是**他申请那一刻你手上有的信息**——征信报告、他填的收入和工作、
他申请的金额。不能用他后来还没还钱的信息，那是作弊。

打完分排序，从高到低批，批到某个分数为止。那个分数叫 **cutoff**。
批得多则规模大但坏账高，批得少则干净但没量。这条权衡就是风控的全部工作。

## 1.2 A 卡在业务链条的哪个位置

```
      客户申请
         │
    ┌────▼────┐
    │  A 卡   │  申请评分卡 ← 本项目
    │ (准入)  │  决定：批不批、给多少额度、什么利率
    └────┬────┘
         │ 批了
    ┌────▼────┐
    │  B 卡   │  行为评分卡
    │ (存续)  │  用开卡后的用卡还款行为，决定提额/降额/预警
    └────┬────┘
         │ 逾期了
    ┌────▼────┐
    │  C 卡   │  催收评分卡
    │ (催收)  │  预测回收概率，决定催收策略和资源投放
    └─────────┘
```

**为什么 A 卡的 KS 天然比 B 卡低**：A 卡只有申请瞬间的一张静态快照；
B 卡有几个月的行为记录（"连续三个月只还最低额""这个月突然刷爆"），信息量差一个量级。
这条要主动说，否则面试官看到 KS 0.247 会以为你做砸了。

## 1.3 七个环节为什么是这个顺序

很多人以为评分卡项目就是"分箱—WOE—逻辑回归"，那只是中间一小段。
真实顺序是这样，**每一步都为下一步提供输入**：

```
① 防泄漏        先确定哪些字段能用。用错字段，后面全白做
     ↓
② vintage       曲线告诉你「观察多久才算数」→ 定出表现期
     ↓
③ 好坏定义      有了表现期，才能在某个时点上说「这人是好是坏」→ 造出 y
     ↓
④ 跨时间切分    有了 y，才能切训练/OOT，才能验证
     ↓
⑤ 建模          分箱/WOE/LR/刻度 ← 大家以为的"全部"其实在这儿
     ↓
⑥ 拒绝推断      修正「样本只有被批过的人」这个偏差
     ↓
⑦ 策略与监控    把分数变成钱和动作
```

**记住这个顺序本身就是一个考点。** 面试官问"你会怎么从零做一个 A 卡"，
上来就说"先分箱"的人，和先说"先定表现期和好坏口径"的人，段位不一样。

# 第四部分　逐环节详解

---

## 环节一　防标签泄漏

### 要解决什么

你在用"这个人后来还没还钱"的信息去预测"这个人会不会还钱"。
这叫标签泄漏，是评分卡项目最致命、也最常见的错误。

### 我怎么做的

**白名单，不是黑名单。**

黑名单的问题是：你永远不知道自己漏了哪个。151 列里 39 列是放款后字段，
漏一个就前功尽弃。所以反过来——默认全部剔除，逐列判定"申请那一刻拿得到吗"，
只有答"是"的才进候选池。

判定结果：

| 判定 | 列数 | 典型例子 |
|---|---|---|
| MODEL 可用 | 79 | FICO、DTI、查询次数、开户数 |
| LEAK 泄漏 | 39 | `last_fico_range_high`、`debt_settlement_flag`、`hardship_dpd` |
| SPARSE 稀疏 | 16 | 联合申请人字段，绝大多数为空 |
| PRICING 定价 | 4 | `grade`、`int_rate`、`installment`、`sub_grade` |
| 其余 | 13 | 标识、自由文本、平台内部字段 |

代码里还加了一道**强制校验**：`check_coverage()` 在跑批开头检查 151 列一列不漏，
有没判定的就直接中止。这条很重要——它保证以后数据加了新列，流水线会主动报错，
而不是"默认放行"悄悄把泄漏字段放进来。

### 第一层追问：举个泄漏字段的例子

`debt_settlement_flag`——这个人有没有进入债务和解程序。
进债务和解的人几乎必然是坏客户，所以这个字段等于直接告诉你答案。

### 第二层追问：`grade` 和 `int_rate` 算不算泄漏

**不算，但也不能用。** 申请人签约前确实看得到利率和等级，
所以它们不是"未来信息"。但它们是 **Lending Club 自家评分模型的输出**。

放进模型有三个问题：① 等于在学别人的模型，不是在学风险本身；
② 换一家机构就没有这些字段，模型搬不走；
③ 监管要你解释每一分的来源，"因为平台给他评了 D 级"不是解释。

我把它们单列成 PRICING 一类，主卡不用，`int_rate` 只留给收益测算算利息收入。
**而且我量化了代价**：加回去 OOT KS 从 0.2473 涨到 0.3042。
这个数字要记住——它是"拒绝走捷径"的价格。

### 第三层追问：你怎么知道自己没漏

三个信号加一个笨办法：

1. **IV 上限报警**。我设了 `IV_CEIL = 0.80`，超过就标出来。
   泄漏字段的 IV 通常高得离谱（`last_fico_range_high` 能到 1.5+）。
2. **KS 超出经验区间**。申请评分卡 KS > 0.5 第一反应是查泄漏，不是高兴。
3. **变量名模式**：带 last / total / recovery / settlement / current 的要重点看。
4. 笨办法：**逐列过数据字典**。这没有捷径，我就是这么做的。

## 环节二　vintage 与表现期

### 要解决什么

"坏客户"不是一个自然存在的标签，是你定义出来的。定义需要回答两个问题：

1. **观察多久**（表现期）——放款后看 12 个月还是 24 个月？
2. **坏到什么程度算坏**（坏定义）——逾期 1 个月还是 3 个月？

vintage 分析回答第一个。

### vintage 到底是什么

按**放款月份**把客户分组（每组叫一个 cohort），
看每组在账龄第 1、2、3…个月的**累计坏账率**，画成一簇曲线。

横轴是账龄 MOB（Months on Book，放款后第几个月），不是日历时间。
这样不同月份放的款可以对齐比较。

它同时回答两件事：
- 曲线什么时候趋缓 → 表现期取多长
- 不同 cohort 的曲线高低 → 哪个时期放的款质量差

### 我怎么做的：一个必须说清的限制

**Lending Club 只给终态快照，不给逐月表现记录。**
也就是说，它只告诉你"这笔贷款最后是还清了还是核销了"，
不告诉你"第 7 个月末它逾期几天"。

所以我是**重建**出来的：`last_pymnt_d` 是最后一次还款的月份，
那么一个账户在账龄 m 时的未还款月数 = m − 最后还款账龄（已结清的除外）。
据此还原任意账龄上的 M0/M1/M2/M3+ 状态。

**这是代理 vintage，不是真 vintage，我在图、日志、README 里都标了。**
主动说这一条，比等面试官问出来强。

重建有三处近似，最要紧的一条：**看不到"逾期—还上"的中途反复**。
`last_pymnt_d` 只记最后一次还款，一个人逾期 3 个月后又还上了，这里会判成一直正常。
所以我的口径严格说是"**终态 M3+**"（停了就再没还过），不是银行常说的"曾经 M3+"，
会略微低估坏客户。无担保消费贷从 90+ 治愈的比例很低，影响有限——
**但这是口径差异，不能含糊成"就是 M3+"。**

### 表现期 18 个月：理由不是"曲线走平"

**这是本项目我最想让你讲对的一节。**

教科书答案是"看曲线在第几个月走平"。但我这条曲线**到 MOB 30 都没走平**：
MOB 24→27 还涨 1.17 个百分点，27→30 涨 1.02 个百分点。
36 期等额本息产品的违约贯穿整个账期，真要等平得等到接近 MOB 36。

所以实际是个**权衡**：

| 表现期 | 最晚可用放款月 | 可用 cohort | 可用样本 | 捕获最终坏账 |
|---|---|---|---|---|
| 12 | 2018-03 | 9 个季度 | 719,326 | 31.5% |
| **18** | **2017-09** | **7 个季度** | **561,237** | **59.0%** |
| 24 | 2017-03 | 5 个季度 | 395,905 | 83.4% |

表现期越长标签越完整，但满足"放款月 + 表现期 ≤ 数据快照月"的 cohort 越少，
跨时间 OOT 越切不开。

选 18 的四条理由，按重要性排：

1. **12 个月只捕获 31% 的最终坏账**，标签太不完整。而且早期违约（首期不还、欺诈）
   和中后期违约（收入恶化、失业）是两类人，只学前者会让卡在正常信用风险上失灵。
2. **24 个月最晚只能用到 2017-03 的放款**，训练期和 OOT 期切不开——
   跨时间验证正是这个项目要补的第一件事，不能为了标签完整把它牺牲掉。
3. **违约的边际强度在 MOB 10~21 见顶、之后逐月回落**。
   18 个月正好罩住整个高发期。这比"曲线走平"是靠谱得多的停表理由。
4. 和零售无担保分期贷 12~18 个月表现期的行业惯例一致。

### 第二层追问：怎么保证各 cohort 可比

必须做**成熟度检验**：只有观察期 ≥ 表现期的 cohort 才能进样本。

最容易犯的错是把未成熟 cohort 的曲线画到底，画出一条假的"越晚的人群越好"。
我的代码里对观察不到的 MOB 直接填 NaN，不让它进图。

这个数据里这一点特别明显：36 期贷款"已到终态"的比例按放款半年是
2015H1 100% → 2016H1 82% → 2017H1 47%。
**如果直接拿 `loan_status` 的终态当标签，越晚的 cohort 坏账率会被系统性低估**，
OOT 一比就是假的下降。这也是我坚持用固定表现期而不是终态的原因。

## 环节三　好坏灰定义

### 我怎么做的

在 MOB 18 这个观察点上：

- **坏**：连续未还款 ≥ 3 个月（M3+）
- **灰**：未还款 1~2 个月（M1~M2），**剔除不建模**
- **好**：当期正常或已结清

| | 样本量 | 占比 | 最终核销率 |
|---|---|---|---|
| 好客户 | 509,684 | 90.81% | 3.45% |
| 坏客户 | 44,581 | 7.94% | **99.24%** |
| 灰客户 | 6,972 | 1.24% | 79.73% |

**坏客户组 99.24% 最终核销，这是标签质量的自检**——说明这个口径抓的确实是坏人。

### 第一层追问：为什么是 M3+

M3+（90 天以上）是巴塞尔框架下违约的通行定义，也是多数机构核销政策的触发线。

定太松（M1+）会把大量只是忘了还款的人算成坏，模型学到的是"健忘"不是"还不起"；
定太紧（M6+）坏样本太少，且需要更长的表现期。

### 第二层追问：灰样本为什么剔除

M1~M2 的客户最终去向分化大，归好会污染好样本，归坏会高估坏账率。
行业通行做法是剔除，并在报告里给出占比。

**占比过高（比如 > 5%）说明表现期或坏定义没选好，要回去调。** 本项目 1.24%，合理。

### 第三层追问（陷阱）：灰样本最终 79.73% 都核销了，凭什么不算坏

**这是整个项目最容易被绕进去的一题。**

79.73% 是观察到 MOB 30 以后才知道的**事后**结果。
而标签只能在 MOB 18 这个**观察点**上打。

一个客户 MOB 18 时才逾期 2 期、MOB 22 才核销，他在 MOB 18 就不是坏客户。
把他算成坏，等于把未来信息塞进标签——**模型上线后根本拿不到这个信息**。

这跟环节一的泄漏是同一件事的两个面：
泄漏是把未来信息塞进**特征**，这里是把未来信息塞进**标签**。两个都不行。

## 环节四　跨时间 OOT

### 要解决什么

你的模型要在几个月后的申请人身上用。用同一批人、同一时间段的数据验证，
证明不了这件事。

### 我怎么做的

- **训练**：2016-01 ~ 2016-12 放款，239,767 笔
- **测试**：训练区间内随机留出 25%，79,923 笔
- **OOT**：2017-01 ~ 2017-09 放款，234,575 笔

上界卡在 2017-09，因为再晚的放款月满足不了"放款月 + 18 个月 ≤ 2019-03 数据快照"。

**两个验证集都要留，作用不同：**

| | 是什么 | 证明什么 | 本项目 PSI |
|---|---|---|---|
| 测试集 | 同期随机留出 | 模型**没过拟合** | 0.0003 |
| OOT | 之后的放款 | 模型**跨时间还成立** | 0.0156 |

测试集的 PSI 0.0003 基本是零——因为它和训练集本来就是同一批人。
**拿随机划分的 PSI 说"模型跨时间稳定"是错的**，那只是随机波动。
（第一版项目就犯过这个错，README 里留着这条记录。）

### 结果

| 样本 | 坏客户率 | KS | AUC |
|---|---|---|---|
| 训练 | 8.30% | 0.2496 | 0.6723 |
| 测试 | 8.30% | 0.2521 | 0.6729 |
| **OOT** | **7.70%** | **0.2473** | **0.6690** |

KS 衰减 0.9%，入模变量 CSI 全部 < 0.03。

### 第二层追问（必问）：KS 0.247 是不是太低了

**不低，这是纯 A 卡该有的水平。** 三条理由：

1. 只用申请时点可得的变量，**不含任何用卡行为**（那是 B 卡的料）
2. 剔除了 `grade`/`int_rate` 这些平台自家评分的输出（加回去能到 0.3042）
3. 样本是 LC 已经筛掉约 94.7% 申请之后剩下的人，**本身同质性就高**

公开文献里 LC 申请变量模型的 AUC 基本在 0.68–0.70，本项目 0.6690，在区间内。

**反过来说**：拿一个 KS 0.45 的"申请评分卡"来面试，第一个该被问的是变量里混了什么。

### 第三层追问：衰减只有 0.9%，是不是太好了

**是数据的性质，不是模型的功劳。**

2016→2017 这段时间 LC 的客群本来就稳定（入模变量 CSI 全 < 0.03）。
换一段人群剧烈变化的时期，同样的模型未必有这个结果。

这条我主动写进了 README 的诚实边界。**主动交代"我的好结果有多少是运气"，
比让面试官问出来强得多。**

## 环节五　建模与对照

### 流程

```
单调分箱 → WOE → IV 筛（0.02 ≤ IV ≤ 0.80）→ 相关性去共线（< 0.70）
→ 逻辑回归 → 系数符号与显著性检验 → VIF → 刻度化
```

70 个变量成功分箱 → IV 关留 33 → 相关性关留 25 → 符号显著性关**入模 16**。

### 三个必须会推的公式

**WOE / IV**
```
WOE_i = ln( (箱i内坏/总坏) / (箱i内好/总好) )      正值 = 这箱比整体更坏
IV    = Σ ( 坏占比_i − 好占比_i ) × WOE_i
```

**KS**：好坏客户累计分布的最大差值，几何上是 ROC 上 TPR − FPR 的最大值。

**刻度化**（约定 odds = 好/坏）
```
score = A − B × ln( p/(1−p) )
B = PDO / ln2                       = 20/ln2 = 28.8539
A = 基准分 − B × ln(基准odds)        = 600 − 28.8539×ln50 = 487.1229
```
校验：好:坏 = 50:1 → 600 分；翻倍到 100:1 → 620 分。

**每箱得分 = −B × 系数 × WOE**，基准分（截距项）= A − B×const = 556.51。
客户总分 = 基准分 + 各变量所在箱得分之和。业务方拿 `23_评分卡.csv` 能手算。

### 三个必须会答的"为什么"

**为什么系数必须为正？**
WOE 越大 = 这箱越坏，模型预测的是坏客户概率。系数为负意味着
"越坏的特征反而降低违约概率"，业务上讲不通。
**这是评分卡和普通分类模型最大的分野：不接受符号反常的变量，哪怕它提升 AUC。**
符号为负九成是共线性，所以符号检验要放在相关性筛选**之后**。

**为什么分箱要单调？**
单调性是**分箱的质量要求，不是淘汰变量的标准**。
不单调通常是箱切太细的噪声，**合箱**就能解决，不是丢变量。
（第一版在这栽过：把不单调当淘汰标准，26 个变量丢了 25 个。）

**为什么缺失单独成箱不填均值？**
因为缺失经常就是信号。`mths_since_last_delinq` 为空意味着**从来没逾期过**，
不是"未知"——填均值会把这个强信号抹成"平均水平的逾期历史"，方向完全反了。

### 对照模型：这一节讲好了是加分项

| 模型 | 训练 KS | OOT KS | 训练→OOT 衰减 |
|---|---|---|---|
| **A 评分卡（LR+WOE）** | 0.2496 | **0.2473** | **0.9%** |
| B XGBoost（原始变量） | 0.3574 | 0.3003 | 16.0% |
| C XGBoost（WOE 变量） | 0.3393 | 0.2925 | 13.8% |
| D 评分卡 + LC 定价变量 | 0.3074 | 0.3042 | 1.0% |

**讲法的关键：先承认 XGBoost 赢了。**

> XGBoost 在 OOT 上比评分卡高 0.053 KS。这个差距不小，我不会说"增益有限"，
> 它就是可解释性的价格。

然后把差距**拆开**（这是真做过才有的东西）：

- 纯算法贡献（C−A）**+0.0452**——树能抓交互和非线性
- 不分箱保留细节（B−C）**+0.0078**——很小，说明分箱本身没损失多少信息
- 加平台自家评级（D−A）**+0.0569**——线性评分卡加个 `grade` 就到 0.3042

**然后抛出那个发现**：

> D 组是线性可解释的评分卡，OOT KS 0.3042，反超了 XGBoost 的 0.3003，衰减只有 1%。
> 我顺手验了个猜想：XGBoost 预测概率与 `sub_grade` 的秩相关是 0.6628，
> 评分卡只有 0.5939。B 组一个定价变量都没用，却更贴近平台自家评级——
> 说明它的增量里相当部分是在用 79 个征信变量把平台的内部评分重建出来，
> 不是发现了评分卡结构抓不到的新风险维度。

**最后才讲为什么还是选 LR**：

1. **可解释是硬约束不是偏好**——个人信息保护法第 24 条对自动化决策有说明义务，
   SHAP 值不是"说明"
2. **单调可控**——政策岗能逐条审；树模型学出的局部非单调既没法解释也容易被薅
3. **上线好监控**——评分卡能定位到"哪个变量的哪一箱变了"，树模型只能看整体 PSI
4. **稳定性 0.9% vs 16.0%**
5. **D 组指了条更实在的路**：与其换算法，不如先补变量

**什么时候我会选 XGBoost**：反欺诈——不需要向欺诈分子解释为什么拒绝。
或者双模型：评分卡做准入和对客解释，树模型做额度和定价，决策链上各管一段。

## 环节六　拒绝推断

### 要解决什么

A 卡只能在**已核准**客户身上建模，但上线后要对**所有**申请人打分。
已核准样本被上一版政策筛过，缺了低分段那一截——这叫**幸存者偏差**。

### 两种方法（都要会讲原理）

**① 重加权（Augmentation）**
建一个"是否被核准"的模型 P(accept|x)，给每个已核准客户 `1/P(accept|x)` 的权重。
长得像被拒客户的那些人被放大，加权后的样本近似代表全体申请人，
用它重训 KGB 得到 AGB。
**前提是 MAR**：核准决策只依赖我们观察得到的 x。这个前提通常不成立。

**② 打包法（Parceling）**
用只含共同变量的评分卡给被拒客户打分，按分数分档，
每档按"该档已核准客户坏账率 × 倍数 k"的比例指定坏客户，再并进训练集重训。
**k 是假设不是估计**（业内常用 2~4），必须做敏感性。

### 我的结果：负面的

| 方法 | OOT KS 变化 |
|---|---|
| 重加权 方案A（不含 FICO，核准模型 AUC 0.6153） | +0.0012 |
| 重加权 方案B（仅 FICO 有值，AUC 0.8499） | +0.0003 |
| 打包法 k=2 / 3 / 4 | −0.0057 / +0.0007 / +0.0010 |

**打包法连符号都跟着 k 变**，说明结论对那个拍脑袋的倍数极度敏感。

### 关键：我把根因查出来了

先做了**共同字段可比性体检**，8 个字段判死 2 个：

| 字段 | 判定 | 理由 |
|---|---|---|
| DTI | **不可用** | 被拒侧均值 125.75、最大 737 万、6.2% 为负 |
| 工作年限 | **不可用** | 被拒侧 72% 挤在"< 1 年"、19% 在"5 年"，核准侧是平滑分布 |

"字段名对得上"不等于"数据可比"。不查这一步，直接拿工作年限建核准模型，
会得出"工作 5 年的人特别容易被拒"这种荒唐结论。

**然后是真正的根因**：

| FICO 档 | 已核准占比 | 被拒占比 |
|---|---|---|
| ≤ 660 | 9.8% | **68.2%** |

已核准样本 FICO 最低就是 660（平台的硬门槛），**分箱边界是已核准样本的值域定出来的**。
68.2% 的被拒客户 FICO 在 660 以下，全部落进同一个边界箱拿同一个 WOE——
**评分卡分不出 634 和 520 的区别，因为它从没见过**。
所以被拒样本的共同变量卡分数中位数只比已核准低 5.7 分。

### 第三层追问：那你这个拒绝推断白做了吗

**没白做，而且这个回答本身就是答案：**

> 拒绝推断的效果**永远无法被验证**——被拒客户的真实表现观察不到。
> 任何"做了拒绝推断后 KS 提升 X"的说法，那个 X 都是在**已核准样本**上算的，
> 而已核准样本恰恰是不需要纠偏的那部分。
>
> 能看的只有三样：系数怎么变、分数分布怎么变、同一通过率下换的是哪批人（swap set）。
> 我三样都看了，swap set 显示同一通过率下只换掉 0.2%~0.5% 的人，
> 而且换入换出人群的坏账率高低在 60%/80%/90% 三档上不一致，看不出稳定改善。
>
> 我把它完整做完，是因为**做完才知道限制在哪儿**。真实项目里被拒客户申请时也拉了征信，
> 变量和核准客户完全重叠、值域也重叠，那时拒绝推断才真正有效。
> 这份公开数据的被拒表只留了 9 个字段且值域不重叠——是**数据的限制，不是方法的限制**。

**还可以加一句加分的**：

> 真正无偏的办法只有一个——**随机放款测试**：按一定比例随机批准本该拒绝的申请，
> 真实观察他们的表现。成本高，但大机构会小比例常年做。

## 环节七　策略、收益与监控

### 7.1 策略表

分数十等分，看每档的坏账率和累计通过率。最高档 2.08%，最低档 18.24%，**相差 8.8 倍**。

### 7.2 收益测算：假设必须单列

| 假设项 | 取值 | 来源 |
|---|---|---|
| **LGD** | **0.8964** | **实测**：61,832 笔已核销，回收率 10.36% |
| 资金成本（年化） | 4.0% | 假设 |
| 运营成本（年化） | 1.0% | 假设 |
| 平均存续期 | 1.6 年 | 假设 |
| 违约时敞口 EAD | 0.75 | 假设 |

**五条里只有 LGD 是算出来的，其余四条是拍的，这句话一定要说。**

件均账：好客户赚 **$1,343**，坏客户亏 **$8,429**——**一个坏客户要 6.3 个好客户来填**。
这个比例才是定 cutoff 的真实依据，光看坏账率不够。

### 7.3 cutoff：在测试集选，在 OOT 验

**这一节的方法论比数字重要。**

在 OOT 上挑分数线等于拿验证集调参——挑出来的点必然在 OOT 上好看，
但好看是因为被挑过。上线时你手里只有建模期数据。

| | 全通过坏账率 | 通过率 | 通过后坏账率 | 降幅 |
|---|---|---|---|---|
| 测试集（**选**） | 8.30% | 82.5% | 6.60% | −20.5% |
| OOT（**验**） | 7.70% | **86.0%** | **6.44%** | −16.4% |

**推荐 cutoff = 543 分。** 理由是**风险上限优先**——坏账率是硬约束，
收益最优点若突破风险偏好就不能选，这是风控和业务最常见的分歧点。

通过率从 82.5% 偏移到 86.0%，差 3.5pp。方向合理（2017 年客群略好），
幅度可接受，**但这恰恰说明分数线不能一次定死**：分布一漂移，
同一个分数对应的审批量就自己跑掉了。生产上这叫 **cutoff 回溯验证**，
上线前必做，上线后每月重做。

### 7.4 敏感性里那条最值钱的

| 假设 | 全通过件均净收益 | 总收益最优通过率 |
|---|---|---|
| 基准 | $532 | 97.5% |
| LGD 0.90→0.70 | $695 | 100% |
| **资金成本 4%→8%** | **−$285** | **2.5%** |

**资金成本翻倍比坏账率翻倍更致命**——整个组合由赚变亏。
这类高息小额分期产品对资金成本的杠杆极高。

而 LGD 这个唯一实测出来的参数，在 0.70~1.00 之间来回调，
推荐 cutoff 只在 543~556 分之间小幅移动。
**结论对唯一实测出来的参数反而不敏感，敏感的全是拍出来的。**

### 7.5 监控：核心矛盾是"指标不同时可得"

| 指标 | 放款后多久能算 |
|---|---|
| 审批率、分数分布 | 当天 |
| 分数 PSI、变量 CSI | 当月 |
| FPD30 / MOB3 | 1–3 个月 |
| MOB6 / MOB9 | 6–9 个月 |
| **KS / AUC** | **18 个月** |

**模型效果真掉下来的时候，你要等 18 个月才能用 KS 证明它掉了。**
所以必须靠前置指标先报警，KS 是事后确认。

我用 2017-10 之后的 **427,348 笔**放款真跑了一遍。跑出来的漂移：

`verification_status` 的 CSI 从 0.093 一路爬到 **0.273（报警）**。钻取到箱：

| | 建模期 | 2018-12 | 变化 |
|---|---|---|---|
| Not Verified | 27.88% | 50.82% | **+22.94pp** |
| Verified | 28.63% | 13.10% | **−15.53pp** |

逐月渐进、无断点跳变 → 判定为**政策缓慢变化**（平台在放松收入核验）。
**动作是重做这个变量的分箱，不是整卡重训**——
拿一个口径已变的变量重训，等于把错误固化进新模型。

### 7.6 两个被数据打回的常识（讲出来很加分）

**① 早期指标的代理性——逐个验，不靠常识**

| 早期指标 | 与 MOB12 坏账率的跨 cohort 秩相关 | p 值 | 可用 |
|---|---|---|---|
| MOB3 | +0.073 | 0.852 | 否 |
| MOB6 | +0.550 | 0.125 | 否 |
| **MOB9** | **+0.829** | **0.006** | **是** |

我本来要写"MOB3 可以当早期代理"，一验根本不成立——MOB3 坏账率只有 0.12% 量级，
季度间差异基本是抽样噪声。**MOB9 才是这份数据上最早的可靠代理**，比 MOB18 提前 9 个月。

这不代表 FPD30 没用：**它是异常报警器，不是精细预测器**。
渠道换了、政策放松了的时候会在一两个月内跳起来，那时不需要统计检验也看得见。

**② PSI 能不能预警 KS 下滑**

分数 PSI vs KS 衰减 秩相关 **−0.097（p=0.674）**；最大 CSI vs KS 衰减 **+0.020（p=0.933）**。
都不显著。

结论不是"PSI 没用"，而是 **PSI 正常不能证明模型还好用**：

> PSI 只能发现"人群变了"这一类失效，发现不了"人群没变但关系变了"——
> 经济下行时同样的征信特征对应更高的违约率，申请人分布纹丝不动，PSI 全绿，
> 但模型已经失效了。2020 年疫情初期大批零售模型就是这么死的。

所以监控方案里**前置指标、早期 vintage、校准度检验、宏观关联四条缺一不可**。

# 第五部分　七个高频陷阱题

**1. "你这 KS 才 0.25，是不是模型不行？"**
→ 见环节四第二层追问。三条理由 + 文献区间 + 反问"KS 0.45 的申请卡您敢用吗"。

**2. "灰样本最后 80% 都坏了，凭什么不算坏？"**
→ 观察点 vs 事后结果。把未来信息塞进标签和塞进特征是同一个错误。

**3. "XGBoost 明明更好，为什么不用？"**
→ 先承认它赢 0.053。再拆来源。再讲 D 组反超。最后讲可解释是硬约束不是偏好。

**4. "拒绝推断没效果，是不是做错了？"**
→ 把根因（FICO 值域不重叠）说出来，再讲"效果永远无法验证"这个方法论限制。

**5. "PSI 都正常，模型应该没问题吧？"**
→ 反过来答：PSI 正常不能证明模型还好用。举疫情的例子。

**6. "cutoff 怎么定的？"**
→ 先说在哪个样本上选（测试集），再说三种口径，再说 OOT 固定验证的偏移。
   最后强调"光看坏账率不够，要算到钱：一个坏客户要 6.3 个好客户填"。

**7. "这个项目和真实工作差在哪？"**
→ 主动说诚实边界那 13 条里最重的 4 条：没上线、代理 vintage、
   拒绝推断无效、收益测算是简化模型。**答得出来说明知道真实流程长什么样。**

# 第六部分　不会答的时候怎么说

**最差的三种反应**：编一个、沉默、"这个我没做过"然后停住。

**标准句式**：

> 这块我没有实际做过。按我的理解应该是 ⟨说出你能推的部分⟩，
> 但我不确定 ⟨明确说出不确定的点⟩。如果是我来做，我会先 ⟨说出验证的办法⟩。

例子——被问"你们怎么做模型上线的灰度发布"：

> 这块我没有实际做过。按我的理解，评分卡的模型件就是一张切点+WOE+系数的表，
> 部署成本很低，所以灰度通常是按流量比例双跑：新旧模型同时打分，
> 只有旧模型的结果进决策，新模型的分数只记录不生效，跑够一个观察周期再切。
> 我不确定的是切换比例和观察周期的行业惯例。如果是我来做，
> 我会先看两套模型在同一批流量上的 swap set——换掉的人多不多、换进来的是不是更好，
> 这个不用等表现期就能看。

**为什么这样答有效**：它证明了三件事——你知道边界在哪、
你能从原理推到具体做法、你知道怎么验证。比硬编强得多。

# 第七部分　术语表（零基础版）

| 术语 | 一句话解释 |
|---|---|
| **A 卡 / B 卡 / C 卡** | 申请评分卡 / 行为评分卡 / 催收评分卡 |
| **MOB** | Months on Book，账龄，放款后第几个月 |
| **vintage** | 按放款月份分组看各组随账龄的坏账率曲线 |
| **表现期** | 放款后观察多久来判定好坏，本项目 18 个月 |
| **观察点** | 打标签的那个时点，本项目 = 放款后第 18 个月 |
| **M1 / M3+** | 逾期 1 个月 / 逾期 3 个月及以上 |
| **FPD30** | First Payment Default，首期逾期 30 天 |
| **灰样本** | 轻度逾期、既不算好也不算坏的客户，通常剔除 |
| **WOE** | 证据权重，`ln(箱内坏占比 / 箱内好占比)`，正值=更坏 |
| **IV** | 信息价值，衡量变量整体区分力，0.02 以下无用 |
| **KS** | 好坏客户累计分布的最大差值，衡量区分能力 |
| **AUC** | ROC 曲线下面积，衡量整体排序能力 |
| **PSI** | 群体稳定性指标，看**分数**分布有没有漂移 |
| **CSI** | 特征稳定性指标，看**单个变量**分布有没有漂移 |
| **OOT** | Out of Time，训练期之后的样本，验证跨时间稳定性 |
| **PDO** | Points to Double the Odds，odds 翻倍对应多少分 |
| **cutoff** | 审批分数线，高于它才批 |
| **LGD** | 违约损失率，违约后损失掉的本金比例 |
| **EAD** | 违约时的风险敞口 |
| **KGB / AGB** | Known Good Bad（只用已核准）/ All Good Bad（含推断的被拒） |
| **swap set** | 同一通过率下两套模型批的人的差集 |
| **标签泄漏** | 用了放款后才产生的信息去预测放款后的结果 |
| **幸存者偏差** | 样本只有被批过的人，缺了被拒的那一截 |
