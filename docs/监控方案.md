# 申请评分卡上线后监控方案

> 本文是设计文档。其中的指标、阈值、动作全部由 `steps/step7_monitoring.py` 实跑验证，
> 数字出处见 `output/60_月度监控报表.csv`、`output/60b_有标签月份效果.csv`、
> `output/62_早期风险指标.csv`、`output/62b_早期指标代理性检验.csv`。

---

## 一、先说清楚监控体系的核心矛盾

**指标不是同时可得的。**

| 指标 | 放款后多久能算 | 说明 |
|---|---|---|
| 审批率、分数分布、分数均值 | 当天 | 决策时就产生 |
| 分数 PSI、变量 CSI | 当月 | 只需要申请时点的变量 |
| FPD30 / MOB3 逾期 | 1–3 个月 | 早期账龄 |
| MOB6 / MOB9 累计坏账率 | 6–9 个月 | 中期账龄 |
| **KS / AUC** | **18 个月** | 要等整个表现期走完才有标签 |

也就是说：**模型效果真掉下来的时候，你要等 18 个月才能用 KS 证明它掉了。**

所以监控体系必须靠前置指标先报警，KS 是事后确认而不是触发条件。
把 KS 当唯一监控指标，做出来的就是一套"事后诸葛亮"看板。

本项目实测（`output/62b_早期指标代理性检验.csv`）：

| 早期指标 | 与 MOB12 坏账率的跨 cohort 秩相关 | p 值 | 可用 |
|---|---|---|---|
| MOB3 | +0.073 | 0.852 | 否 |
| MOB6 | +0.550 | 0.125 | 否 |
| **MOB9** | **+0.829** | **0.006** | **是** |

MOB3 在这份数据上不是可靠代理——坏账率只有 0.12% 量级，季度间差异基本是抽样噪声。
但这不代表 FPD30 没用：它是**异常报警器**不是精细预测器，渠道换了、政策放松了的时候
会在一两个月内跳起来，那时不需要统计检验也看得见。

## 二、监控指标与阈值

### 2.1 日度（自动跑，异常才推送）

| 指标 | 阈值 | 超阈动作 |
|---|---|---|
| 评分服务可用率 | < 99.9% | 立即告警运维 |
| 变量缺失率 | 任一入模变量单日缺失率较前 7 日均值偏离 > 10pp | 查数据源，疑似上游接口故障 |
| 打分失败率 | > 0.1% | 查边界值与新类别 |
| 分数均值 | 较前 30 日均值偏离 > 3 个标准差 | 查是否有批量异常申请 |

### 2.2 月度（核心报表）

| 指标 | 正常 | 关注 | 报警 |
|---|---|---|---|
| 分数 PSI（对建模期） | < 0.10 | 0.10 – 0.25 | ≥ 0.25 |
| 单变量 CSI（对建模期） | < 0.10 | 0.10 – 0.25 | ≥ 0.25 |
| 审批率 | 较上月变动 < 5pp | 5 – 10pp | ≥ 10pp |
| 高分段（前 20%）占比 | 较建模期变动 < 5pp | 5 – 10pp | ≥ 10pp |

### 2.3 季度（效果）

| 指标 | 正常 | 关注 | 报警 |
|---|---|---|---|
| KS 相对建模期衰减 | < 10% | 10% – 20% | ≥ 20% |
| vintage MOB6 / MOB9 坏账率 | 在近 4 个 cohort 的 ±1 倍标准差内 | 1–2 倍 | > 2 倍 |
| 实际坏账率 vs 预测坏账率（校准度） | 偏离 < 10% | 10% – 25% | ≥ 25% |

> 阈值 0.10 / 0.25 是行业通行的经验值，不是本项目算出来的。
> 落到具体机构应该按自己的历史波动重新定：
> 取建模期内各月 PSI 的分布，用 P95 当关注线、P99 当报警线，比照搬经验值靠谱。

## 三、超阈之后做什么

**报警之后第一件事是定位，不是重训。** 评分卡的结构优势就在这儿——
能直接打开看是哪个变量的哪一箱在变。

### 3.1 先分清「人群变了」还是「口径变了」

| 症状 | 判断 | 动作 |
|---|---|---|
| 各箱占比此消彼长、变化连续、能和渠道/营销动作对上时间 | 人群变了 | 重新分箱；若 KS 同步下滑则重训 |
| 某一箱占比突变或归零、缺失率跳变、变化发生在系统上线日 | 口径变了 | **先停用该变量并修数据源**，修好前不许重训 |
| 单变量 CSI 高但分数 PSI 正常 | 局部漂移，被其他变量抵消 | 观察，不动模型 |
| 分数 PSI 高但各变量 CSI 都正常 | 变量间相关结构变了 | 查交叉分布，考虑重训 |

拿一个口径已变的变量去重训，等于把错误固化进新模型——这是实务里最常踩的坑。

**本项目跑出来的真实例子**（`output/60_月度监控报表.csv`）：
假设 2017-10 上线，之后 15 个月里 `verification_status` 的 CSI 从 0.093 一路爬到 0.273（报警）。
钻取到箱：

| 箱 | 含义 | 建模期占比 | 2018-12 占比 | 变化 |
|---|---|---|---|---|
| 0 | Not Verified | 27.88% | 50.82% | **+22.94pp** |
| 1 | Source Verified | 43.49% | 36.08% | −7.41pp |
| 2 | Verified | 28.63% | 13.10% | **−15.53pp** |

变化是逐月渐进的、没有断点式跳变，更像平台在这段时间逐步放松了收入核验要求，
属于"政策缓慢变化"。动作是：先和业务确认核验规则是否调整，
确认后把这个变量的分箱重做（而不是整卡重训），观察 CSI 是否回落。

### 3.2 动作分级

```
KS 衰减 >= 20%                  -> 立即重训；同时冻结 cutoff 下调申请
分数 PSI >= 0.25                -> 查渠道/口径，确认后重新分箱或重训
单变量 CSI >= 0.25              -> 核查该变量数据源，必要时剔除该变量重训
KS 衰减 10%~20%                 -> 关注区：排查近期政策/渠道变更，准备重训样本
PSI 或 CSI 在 0.10~0.25         -> 加密到每周监控，同步检查审批率与通过客户结构
全部正常                         -> 保持月度监控
```

这段逻辑在 `src/monitoring.py: action_for()` 里是代码，不是文档——
监控方案只报数不给动作，等于没做监控。

### 3.3 重训的触发与节奏

- **定期重训**：无论指标好坏，每 12 个月重训一次。模型不会因为指标正常就永远有效。
- **触发重训**：满足上面任一报警条件。
- **重训样本**：滚动向前取最近一个完整表现期之后的放款，旧样本按时间衰减加权。
- **重训后必须做**：新旧模型在同一 OOT 上对拍、swap set 分析（换掉哪批人）、
  切换后前 3 个月双跑观察。**不许直接替换。**

## 五、一条必须写进方案的限制

本项目实测：分数 PSI 与 KS 衰减的秩相关 −0.097（p=0.674），
最大 CSI 与 KS 衰减的秩相关 +0.020（p=0.933）——**都不显著**。

不要把这读成"PSI 没用"。这段时间 LC 的客群本来就稳（PSI 全在 0.03 以下），
KS 的月度波动主要是抽样噪声，两个变量都接近常数，自然测不出相关。

真正的含义是：**PSI 正常不能证明模型还好用。**

PSI 只能发现"人群变了"这一类失效，发现不了"人群没变但关系变了"——
比如经济下行时，同样的征信特征对应更高的违约率，申请人分布纹丝不动，
PSI 全绿，但模型已经失效了。2020 年疫情初期大量零售模型就是这么废的。

所以监控方案必须同时有：
1. **前置指标**（PSI/CSI）——抓人群漂移
2. **早期 vintage**（MOB6/MOB9）——抓"关系变了"
3. **校准度检验**（实际坏账率 vs 预测坏账率）——抓整体水平漂移
4. **宏观关联**（失业率、利率）——当外部环境突变时主动复核，不等指标报警

四条缺一不可，只看 PSI 是不够的。
