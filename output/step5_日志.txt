  5.1  共同变量盘点：哪些能用，哪些不能用
========================================================================

直接拿来建核准模型会得出荒唐的结论。逐个查：

  日期 可用（有偏移）          已核准侧是放款月、被拒侧是申请日，LC 放款滞后申请约 2~4 周      NaN      NaN     NaN

       这是这份公开数据的硬限制，结论的可靠性要打折，后面会再说一次。

========================================================================
  5.5  方法二：打包法（Parceling）
========================================================================
用只含共同变量的评分卡给被拒客户打分，按分数档指定推断坏标签，
每档推断坏账率 = 该档已核准客户坏账率 x k。k 是假设，做 (2.0, 3.0, 4.0) 三档敏感性。
用于打包的被拒样本 239,767 笔（FICO 有值，抽样到与训练集同量级）
    共同变量评分卡入模：['fico_range_low', 'addr_state']
    它在已核准训练集上的 KS = 0.1405（只有 3 个变量，弱是正常的）
    分数对比：已核准中位数 554.6，被拒中位数 549.0，差 5.7 分

-- 为什么这个差只有几分：评分卡不会外推 --
    共同变量卡是在**已核准样本**上分的箱。已核准样本 FICO 最低 660（LC 的硬门槛），
    所以最低那一箱的下界就是 660。被拒客户 FICO 中位数 634、四分位下界 592，
    全部落进同一个最低箱，拿同一个 WOE——评分卡看不出 634 和 520 有什么区别。
          已核准占比    被拒占比
<=660    0.0982  0.6824
660-680  0.3360  0.1142
680-700  0.2408  0.0777
700-720  0.1582  0.0471
>720     0.1668  0.0785
    被拒样本有 68.2% 落在 <=660 这一档，已核准只有 9.8%。
    这是打包法在这份数据上失效的**根本原因**，不是 k 选得不对：
    分箱边界是已核准样本的值域定的，对值域外的人群没有分辨力。
    真实项目里被拒客户的征信变量取值范围和核准客户是重叠的（同一套征信），
    不会出现这种整体落到边界外的情况。
    k=2.0: 被拒样本推断坏账率 19.73%，打包后共同变量卡 OOT KS 0.1587 -> 0.1530（-0.0057）
    k=3.0: 被拒样本推断坏账率 29.61%，打包后共同变量卡 OOT KS 0.1587 -> 0.1593（+0.0007）
    k=4.0: 被拒样本推断坏账率 39.45%，打包后共同变量卡 OOT KS 0.1587 -> 0.1597（+0.0010）

   注意这里比较的是**只含共同变量的评分卡**打包前后的变化，
   因为被拒样本没有其余 76 个征信变量，没法把它们并进主卡重训。
   这是打包法在这份数据上的结构性限制：被拒侧变量太少，推断样本进不了主模型。

========================================================================
  5.7  结论：拒绝推断在这份数据上到底值不值
========================================================================
1. 重加权后，OOT（已核准样本）上的 KS 变化：
     AGB[方案A_不含FICO]              0.2473 -> 0.2485  （+0.0012）
     AGB[方案B_仅FICO有值样本]           0.2473 -> 0.2476  （+0.0003）
   但这个数字不能当成「拒绝推断的效果」——见 5.4 末尾那段。
2. 打包法在 k=(2.0, 3.0, 4.0) 三档下，共同变量卡的 OOT KS 变化见 44_打包法敏感性.csv，
   幅度都很小，且随 k 变号——说明结论对那个拍脑袋的倍数很敏感。
3. swap set 显示两套卡在同一通过率下换掉的人群只占 0.2%~0.5%，
   而且换入换出人群的坏账率高低在不同通过率上并不一致，看不出稳定的改善。
4. 根本限制有两层：
   (a) 被拒侧只有 3 个干净的共同变量，主卡用了 16 个。拒绝推断只能纠正
       「金额 + FICO + 地域」这三个维度上的选择偏差，其余维度纠不了。
   (b) 更要命的是 5.5 那个发现：已核准样本 FICO 下界是 660（LC 的硬门槛），
       分箱边界由它决定，而大部分被拒客户 FICO 在 660 以下，
       整体落进同一个边界箱——评分卡对值域外人群没有分辨力。
       这也解释了为什么两种方法的效果都接近于零。

[诚实结论] 在这份数据上，拒绝推断带来的提升很有限，而且无法被验证。
   我仍然把它做完整，是因为：①真实项目里必须做，流程要跑通；
   ②做完才知道它的限制在哪儿——限制本身是结论的一部分。
   真实项目里做拒绝推断，前提是被拒侧能拿到和核准侧同样的征信变量
   （申请时都拉过征信，数据在自己手里），那时候它才真正有效。
   这份公开数据的被拒表只留了 9 个字段，这是数据的限制，不是方法的限制。
